Claude 换号台 · Windows

用途
使用你自己订阅账号的 claude setup-token。保留 ~/.claude 的普通登录、
插件、CLAUDE.md、记忆、权限和 MCP 配置。套餐取手填或已有本地记录。
Windows 还支持登记多个普通登录账号，每个账号由 Claude Code 单独保存和续期。

添加普通账号
在 Clash Verge 里选好该号对应的代理节点，确认网页登录用的浏览器也走该节点。
点击「添加普通账号」，填写名字、专用本机 HTTP 端口（例如 http://127.0.0.1:31004）
和固定出口 IP。「测一下」会经这个端口核对出口。复制官方登录链接，在本机浏览器
完成一次 Claude Code 授权。看到「已添加」后即可使用。登记期间可以继续用原账号。
每张卡占用独立端口和出口 IP。默认普通登录和新卡共用出口时必须是同一账号。
同一个个人账号已有令牌卡时，请选择原卡登记普通登录。端口和出口锁定为原值；
官方返回的组织和个人订阅匹配后，两张卡都保留。原卡缺少可核对的组织时会提示。
Clash 的域名规则也会影响浏览器。可在授权用的浏览器里打开
https://claude.com/cdn-cgi/trace 核对 ip= 那一行；换号台的「测一下」只检测所填端口。
后续点该卡的「切换」，核对窗口清单和恢复权限。受管终端和后台停止后，
每个窗口按自己的会话编号接回原对话。终端代理由启动器设置，不用手输环境变量。
节点和端口的对应关系要在 Clash 保持固定；浏览器走哪条线路仍由你控制。
登录过期或官方撤销授权时需要重新授权。

添加与检查
先从该账号原有的固定出口运行官方 claude setup-token，再把令牌粘贴进管理器。
为账号填写本机 HTTP 代理。固定出口 IP 可以留空，添加时会检测两个官方域名，
确认出口一致后保存绑定。编辑已有账号时留空会保留原绑定，不会自动接受变化后的出口。
也可以点“检测出口”先获取 IP，这个操作不使用令牌。添加、切换、查用量前会分别
访问 claude.ai 和 api.anthropic.com 的官方 trace 地址，比对精确 IP。
本程序不修改 Clash 或服务器，不创建代理节点。代理后续改路由仍可能改变出口，
因此应在代理软件中固定账号线路。出口检查不是操作系统级网络隔离。

用量
平时换号台不主动发模型请求或调用 OAuth usage/profile。受管会话通过 Claude Code 的
statusLine 接收自身请求返回的 5 小时、7 天额度。每条记录按启动时绑定的账号、
PID 和出生时间核对；切号后的旧回报不能写到新账号名下。后台还须核对接续关系、
账号资料代际和作业归属，已接管的后台才能上报，不用当前选中账号猜归属。
缺少某个额度窗口时保留上次记录，不编造额度；7 天 Fable 沿用旧记录。
重置时间过后，如果没有新的用量记录，界面会提示额度已重置。

只有手动点击查询才会启动一次独立的官方 Claude Code，使用被查询账号的 Token
和固定代理发送很短的请求，从 stream-json 的 rate_limit_event.unifiedWindows
读取额度。不会切换当前账号，不使用 /usage 缓存；没有响应额度就明确报未查到。
这会花少量额度；原生 CLI 没有保证恰好只生成 1 token 的参数。
同一时间只允许一次查询；完成、失败、超时均回收查询进程及其子进程。
默认最长 90 秒。查询结束后独立临时目录也被删除，不积累 Claude 进程。

普通登录查询只读有效 accessToken，不复制 refreshToken，不续期或改写登录凭据。
过期或不足 60 秒时请先在官方 CLI 正常使用、完成续期后再查。
普通登录代理取原来的 Claude 设置，未设置则用 127.0.0.1:7897；首次绑定固定出口，
之后查询、启动和切回前都检查。普通登录自动续期后，原窗口和受管后台继续用本账号的
Claude Code 响应更新额度，无需重开。首次启动先续期时，等原生账号资料确认后开始收数。
换号后，旧窗口的迟到读数不会写进新号。无法确认身份时暂不收数；手动查询仍严格核对凭据。
请使用原生登录或换号台；只替换凭据文件不能可靠识别账号。
缓存不包含凭据。

受管账号资料
Windows 受管会话的历史、设置文件和插件仍使用默认目录；全局资料单独放在
该目录内，避免令牌账号请求带上普通登录账号的 UUID。不改 Desktop 使用的外层资料。
全局偏好、MCP 与项目信任只在首次建立时复制；外层之后的更改不会自动同步。
在受管终端执行 claude mcp 会使用受管资料；MCP OAuth 仍跟随各账号的凭据目录。

导出 CPA JSON
当前账号和账号卡片菜单可选择“导出 CPA JSON”，再选择保存位置。
普通登录导出 CPA 所需的 access_token、refresh_token、真实到期时间和身份信息；
setup token 导出 access_token 和 is_setup_token 标记，不伪造 RT 或到期时间。
导出只读凭据，不联网、不续期，不改写 Claude 登录文件，也不改变当前账号。
普通登录的 AT 即使已过期仍按原样导出，后续由 CPA 使用 RT 续期。
CPA 与本机同时使用同一份 RT 续期可能冲突，导致其中一端需要重新登录。

导出是包含完整凭据的明文 JSON，请妥善保管，不要发送给他人。
默认保存到本机数据目录 cpa-exports，禁止保存到 OneDrive 或覆盖登录/内部数据文件。
文件为 UTF-8 无 BOM，限当前 Windows 用户和系统读取；界面只收到保存路径。
两种文件在 CPA 中均默认停用（disabled:true），并带不可连接的阻断代理，
不照抄电脑上的本机代理。CPA 可能给停用账号自动续期，因此不能只依靠停用开关。
上传后先在 CPA 替换为该账号的服务器端代理，核对两个 Claude 地址的出口均与原固定 IP 相同，
再启用账号。导出不会替 CPA 检测出口，也不会自动上传或启用任何账号。

切换与恢复
Windows 切换先列出受管窗口、后台任务和权限模式，确认后正常退出这些 Claude，
停止对应的原生后台会话，确认任务清空，再保存新账号和代理，原终端逐个恢复。
每个窗口用退出前的完整 sessionId；有后台接续时沿记录找到最新的末端 sessionId。
不用 -c：-c 是当前目录最近的对话，不是“这个终端刚才关闭的对话”。
权限可以保持原样、改成普通权限，或由你显式选择完全权限。
清空 /clear 后没发过消息的窗口恢复为空白新会话，不擅自找回 clear 前的内容。

有草稿、弹窗、正在工作、无法核对的状态或未受管的同一 CLI 会话时，先阻止切换，
不替你清空草稿或选择弹窗。停止失败则不切新号，恢复已经退出的窗口；
换号成功但个别窗口恢复失败，可点“重试恢复”，不会回退到旧账号。
自动退出取决于终端和 Claude Code 版本。切换预览会显示每个窗口的状态及需要手动处理的原因。
已经运行的旧版启动器不能直接接管；更新后需要正常退出并从新版入口重新进入。

选择仍只存在换号台数据库，不修改 Windows 用户环境变量或共享普通登录凭据。
令牌只放在新进程的环境里。代理同时放在该进程环境和 --settings 内联配置里，
不会写入共享 settings.json；普通用户/项目 settings 热更新也不会改掉该进程的代理。
HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 及小写形式统一；NO_PROXY 仅保留本机回环，
供本地 MCP / 桥使用。父终端里的 7897 或 NO_PROXY=* 不会覆盖 setup 账号的线路。
终端入口包含 PowerShell 5.1 / 7 的标记配置块、claude.ps1，和 cmd 使用的 claude.com。
原生 claude.exe 保持原样；不覆盖其他工具的同名文件。cmd 依赖默认 PATHEXT 中
.COM 排在 .EXE 前面。修改前留加密备份。
Windows Terminal 与经典控制台的 PowerShell、cmd 已用假环境测试。
经典控制台会使用原生非全屏渲染器，避免 2.1.318 首帧错位；退出后恢复输出模式。
IDE 插件及直接执行 exe 不经过本助手，不自动停止或恢复。
Claude Desktop 不在受管作业对象内，不按进程名称结束它。
显式运行 claude.exe/完整 exe 路径也会绕过启动入口。
setup token 的 /status 应显示 CLAUDE_CODE_OAUTH_TOKEN；其旧邮箱资料不一定代表实际令牌。
项目或 IDE 单独配置的认证会影响结果。终端助手检查当前项目配置；
管理器无法枚举所有未打开项目或 IDE 的私有设置。

认证和代理冲突
API key、AUTH_TOKEN、apiKeyHelper、云提供商开关、固定 OAuth token 或与账号
不一致的托管策略代理会阻止启动。普通用户/项目代理由该进程的内联设置覆盖。
请处理提示的具体认证冲突；本程序不改 Claude settings、登录文件或托管策略。
令牌账号会使用按账号固定的专用凭据存储目录，里面不放普通登录凭据。
这样原生后台服务会保留该账号的环境 Token，不再读取共享普通登录的 Token。
设置和对话历史仍共用默认目录。MCP 的 OAuth 登录也在凭据存储里，因此这类 MCP
可能需要在该令牌账号下重新授权；MCP 配置本身保留。不能复制普通登录凭据进去。

回到普通登录
通过同一批量流程退出受管对话并恢复为本机已有的普通登录；不执行 /logout 或 /login。
从旧版升级时，只清理仍与旧版记录完全一致的本程序用户环境值；手动改过的值保留。
启动器还会去掉旧终端里可确认属于旧版的残留变量，不恢复旧 token 快照。
删除当前账号会回到普通登录，不会自动选另一个账号。
若手工设置的其他认证仍存在，普通登录可能仍被覆盖；界面会列出能检测的冲突。

数据
账号与检查缓存在 %LOCALAPPDATA%\ClaudeAccountManager。
令牌、原环境备份、事务记录、PowerShell 原文件备份用 Windows DPAPI CurrentUser
加密。只有令牌尾六位返回给界面；完整令牌不写日志或命令行。
运行中的 Claude 必须在进程环境中持有明文令牌，但新版不再把它写进 Windows
用户环境变量或命令行。代理命令行参数只包含本机地址，不包含令牌或住宅代理密码。
升级到数据格式 v3 后，主程序和终端助手都需要使用 v0.2.2 或更新版本。
数据只能用保存时的 Windows 用户身份在本机解密。

卸载配置块
先使用“普通登录”，再在 PowerShell 运行：
  & "$env:LOCALAPPDATA\ClaudeAccountManager\bin\cam-launcher.exe" --uninstall-hooks
这会再次清理仍归本程序所有的用户环境值，并删除标记配置块和本程序的 claude.ps1 / claude.com；保留账号数据、
加密备份和用户的其他 PowerShell 配置。关闭旧终端再打开即可卸载函数。
不要在仍需使用时删除 bin 里的助手程序。
